# Account: справка по объектам

Здесь описаны данные и методы сервиса. Нужные изменения для ЛР1 перечислены в [TASK.md](TASK.md).
Часть методов уже реализована в заготовке, остальные добавляются по мере выполнения работ.

## Данные и поведение

`Account` хранит баланс счёта. Изменение остатка выполняется его методами, а `AccountService` организует поиск счёта и применение дополнительных ограничений.

| Метод | Назначение |
|---|---|
| `Account(account_id, customer_id, balance: Money)` | Создаёт счёт со статусом `ACTIVE`. |
| `deposit(amount)`, `withdraw(amount)` | Зачисляет или списывает сумму. Нужны статус `ACTIVE`, положительная сумма и валюта счёта. |
| `check_withdrawal(amount) -> CheckResult` | Проверяет возможность списания без изменения остатка. |
| `block()`, `close()` | Блокирует или закрывает счёт. Закрытие разрешено для `ACTIVE` и `BLOCKED` только при нулевом балансе. |

Списание не может сделать баланс отрицательным. Недопустимые переходы состояния вызывают `INVALID_STATE`.

`AccountService.check(account_id, amount) -> CheckResult` проверяет операцию без списания. Метод `withdraw(account_id, amount) -> Money` сначала выполняет обязательные проверки счёта, затем дополнительные правила и только после этого вызывает `Account.withdraw()`. При отказе он вызывает `DomainError(code)` и сохраняет баланс.

Общий интерфейс дополнительных правил — `WithdrawalRule.check(account, amount)`. `MaximumWithdrawalRule(maximum)` ограничивает сумму операции, `MinimumBalanceRule(reserve)` — остаток после неё. Эти правила не заменяют обязательную проверку средств.

`Money` содержит сумму `Decimal` и валюту. Значение должно быть конечным, неотрицательным и точно представимым с двумя знаками после запятой. Поэтому `Decimal('1.000')` допустим, а `Decimal('1.001')` — нет. Значения разных валют нельзя складывать. В ЛР2 проверки `Money` нужно дополнить; в остальных работах класс предоставлен готовым. Хранилище и вспомогательные проверки уже реализованы.

## Работа с готовым кодом

Обращение к сервису выполняется через `app/api.py`. Разрешённые файлы указаны в [TASK.md](TASK.md).
Проверки используют подготовленные данные и не зависят от работы других групп.

Функции `create`, `make`, `call` и `view` связывают готовый API с реализацией. Используемые ими функции сервисного модуля должны сохранять сигнатуры. Сам `app/api.py` не редактируйте.

До ЛР5 сборка предоставлена готовой. Нужные объекты могут создаваться в сервисном модуле; `assembly.py` менять не нужно.

`Money` находится в `app/domain/money.py`. Его разрешено менять только в ЛР2; в других работах используйте готовую реализацию.

## Ошибки и результаты

`DomainError` содержит код ошибки. При отказе проверки состояние объекта не должно меняться.
Ошибка переданной зависимости не заменяется успешным результатом. Конкретные коды и примеры
приведены в задании и открытых тестах.
