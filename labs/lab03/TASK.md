# ЛР3. Дополнительные правила списания

Вариант: **Account**.

## Что дано

Предметные объекты, внешний API и вспомогательные типы уже подготовлены. В `app/domain/withdrawal.py` даны заготовки общего интерфейса и двух исполнителей. Их поведение и основной метод `AccountService.check()` требуется завершить самостоятельно. Сигнатуры сохранены; новые слои и выбор архитектуры не нужны.

## Задание

### Шаг 1. Реализуйте общий интерфейс и два поведения

Реализуйте абстрактный класс `WithdrawalRule` и два наследника.

`MaximumWithdrawalRule(500 EUR)` разрешает сумму не более `500 EUR`; иначе возвращает `WITHDRAWAL_LIMIT_EXCEEDED`. `MinimumBalanceRule(50 EUR)` требует, чтобы `balance - amount >= 50 EUR`; иначе возвращает `MINIMUM_BALANCE_REQUIRED`.

Валюта настройки должна совпадать с валютой суммы, иначе вызывается `CURRENCY_MISMATCH`. Сервис сначала выполняет обязательную проверку счёта, затем вызывает общий метод `check()` у правил.

### Шаг 2. Соберите путь вызова в `AccountService.check()`

Проверка счёта `check_withdrawal(amount)` предшествует дополнительным правилам. Первый отказ сохраняет баланс; только успешный `withdraw()` вызывает списание у счёта один раз. Не выбирайте алгоритм по конкретному классу исполнителя.

### Шаг 3. Проверьте повторное использование

Баланс 200: списание 30 → 170; попытка списать 171 → `INSUFFICIENT_FUNDS` и прежние 170; списание 20 → 150.

## Примеры и границы

- Максимум `500 EUR`: сумма `500` допустима, `500.01` — нет.
- Баланс `100 EUR`, резерв `50 EUR`: списание `50` допустимо, `50.01` — нет.
- Нулевой резерв допускает полное списание.

Последовательности и конфигурации дополнительно проверяются в `tests/test_progression.py`. Прочитайте ожидаемый результат каждого сценария до реализации.

Все проверки открыты: `tests/test_contract.py` и `tests/test_review_contract.py`.
