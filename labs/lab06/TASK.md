# ЛР6. Ограничение долей остатка

Вариант: **Account**.

## Что дано

Основные правила работают. Ограничение долей текущего остатка пока не реализовано. Новая редакция также требует сочетать расширение с существующим поведением. Каркасы дополнительных типов даны; основной алгоритм сервиса уже готов.

## Задание

### Шаг 1. Завершите предметное расширение

Добавьте `MaximumShareRule(share=Decimal('0.50'))`. Оно разрешает `amount <= balance.amount * share`; иначе возвращает `WITHDRAWAL_SHARE_EXCEEDED`. Порог перед сравнением не округляйте.

Доля должна быть конечной и удовлетворять `0 < share <= 1`, иначе вызывается `INVALID_CONFIG`. Подключите правило в сборке без изменения основного алгоритма.

### Шаг 2. Группа правил с тем же интерфейсом

Добавьте `WithdrawalRuleGroup(rules)` как `WithdrawalRule`. Сохраните `tuple(rules)`, не копируя объекты. Каждый элемент реализует `WithdrawalRule`, иначе `INVALID_CONFIG`. Метод `check(account, amount)` вызывает правила по порядку, проверяет `CheckResult` (`INVALID_RESULT`) и возвращает первый отказ; последующие правила не вызываются. Пустая группа разрешает; исключения передаются наружу. Допустима группа внутри группы.

### Шаг 3. Подключите и сравните конфигурации

В сборке стандартные правила вместе с новым правилом объедините в `WithdrawalRuleGroup`, а сервису передайте список из этой группы. Явно переданный набор не подменяйте. Проверки самого предметного объекта остаются обязательными. Изменение исходного списка не меняет группу; изменение самого правила видно, потому что объект не копируется.

### Шаг 4. Обязательная практическая часть

В `withdrawal.py` реализуйте `MinimumWithdrawalRule(minimum)` через `WithdrawalRule`. Порог — положительный `Money`, иначе `INVALID_CONFIG`. При сумме ниже порога возвращайте `WITHDRAWAL_TOO_SMALL`, равенство разрешайте, валюту проверяйте. Продемонстрируйте через переданный набор правил.

## Примеры и границы

- Баланс `100`, доля `0.5`: сумма `50` допустима, `50.01` — нет.
- После списания `50` следующий порог равен `25`.
- Доля `1` не отменяет обязательные проверки счёта; значения `0` и `1.01` недопустимы.

Последовательности и конфигурации дополнительно проверяются в `tests/test_progression.py`. Прочитайте ожидаемый результат каждого сценария до реализации.

Все проверки открыты: `tests/test_contract.py` и `tests/test_review_contract.py`.
